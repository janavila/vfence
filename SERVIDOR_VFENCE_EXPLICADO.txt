VFENCE MONITOR — REFERÊNCIA TÉCNICA DO SERVIDOR
================================================

1. FINALIDADE
-------------

O VFence Monitor é um serviço local para aquisição, persistência e exibição de
telemetria de coleiras bovinas. A aplicação é projetada para Raspberry Pi 3 e
opera sem dependência obrigatória de internet.

O geofencing não é executado pelo servidor. A coleira calcula a zona e transmite
o resultado. O servidor trata esse resultado como telemetria.


2. FLUXO DE DADOS
-----------------

Coleira / GPS / Geofencing
    -> LoRa 915 MHz
    -> Gateway ESP32 / SX1276
    -> USB / Serial
    -> SerialReader
    -> Parser VFence
    -> SQLite
    -> API FastAPI / WebSocket
    -> VFence Monitor


3. COMPONENTES
--------------

app/main.py
    Inicialização do serviço, ciclo de vida FastAPI, rotas HTTP, WebSocket e
    distribuição de arquivos estáticos.

app/config.py
    Leitura das variáveis de ambiente e definição dos valores padrão.

app/protocol.py
    Validação dos formatos legado e VFence V1. Verifica comprimento, número de
    campos, tipo, coordenadas, zona e valores numéricos.

app/serial_reader.py
    Aquisição Serial assíncrona, reconexão, modo mock, persistência e publicação
    em tempo real.

app/database.py
    Inicialização e acesso transacional ao SQLite.

app/models.py
    Estado interno do gateway.

app/realtime.py
    Registro das conexões WebSocket e broadcast de telemetria.

app/templates/index.html
    Estrutura do painel VFence Monitor.

app/static/css/style.css
    Sistema visual e layout responsivo.

app/static/js/app.js
    Carregamento inicial da API, atualização WebSocket, métricas, tabela, mapa e
    eventos.


4. PROTOCOLO
------------

Legado:

    Recebido: VFENCE_TESTE_630 | RSSI: -103 dBm | SNR: 6.50

VFence V1:

    V1|COL01|POS|-31.306119|-54.063935|SEGURO|12|0.90|630

Campos V1:

    version | collar_id | type | latitude | longitude | zone |
    satellites | hdop | sequence

Zonas aceitas:

    SEGURO
    ATENCAO
    CRITICO
    FORA
    GNSS_INVALIDO

O protocolo e os valores internos não são traduzidos. Rótulos diferentes são
aplicados somente na interface.


5. PERSISTÊNCIA
---------------

collars
    Último estado conhecido de cada coleira.

telemetry
    Registro de todos os pacotes válidos recebidos.

events
    Registro de transições de zona. Um estado repetido não gera novo evento.

Banco padrão:

    sqlite:///./vfence.db


6. CONTRATO HTTP
----------------

GET /api/health
GET /api/gateway
GET /api/collars
GET /api/collars/{collar_id}
GET /api/collars/{collar_id}/telemetry
GET /api/events
WS  /ws

Todos os nomes de campos utilizam snake_case. Uma coleira inexistente retorna:

    HTTP 404
    {"detail":"collar_not_found"}


7. TEMPO REAL
-------------

O endpoint /ws envia dois tipos de mensagem:

gateway
    Estado da interface Serial.

telemetry
    Pacote validado, estado consolidado da coleira e evento opcional.

O frontend reconecta o WebSocket automaticamente após perda da conexão.


8. MODO MOCK
------------

Ativação:

    VFENCE_MOCK_SERIAL=true

O gerador publica uma unidade COL01 e alterna as zonas em intervalo configurado
por MOCK_INTERVAL_SECONDS. O modo usa o mesmo parser, banco, API e WebSocket da
operação Serial.


9. OPERAÇÃO
-----------

Inicialização:

    uvicorn app.main:app --env-file .env --host 0.0.0.0 --port 8000

Painel:

    http://IP_DO_RASPBERRY:8000

OpenAPI:

    http://IP_DO_RASPBERRY:8000/docs

Parada manual:

    Ctrl+C


10. LOGS
--------

Formato:

    YYYY-MM-DD HH:MM:SS [LEVEL] module: message

Exemplo:

    2026-09-24 14:32:01 [INFO] serial_reader: gateway connected (/dev/ttyUSB0)

Eventos registrados incluem inicialização, tentativa de conexão, conexão,
desconexão, pacote recebido, pacote rejeitado e transição de zona.


11. OPERAÇÃO SERIAL NO RASPBERRY PI
-----------------------------------

Detecção:

    ls /dev/ttyUSB*
    ls /dev/ttyACM*

Permissão:

    sudo usermod -a -G dialout $USER

Configuração típica:

    VFENCE_MOCK_SERIAL=false
    SERIAL_PORT=/dev/ttyUSB0
    SERIAL_BAUD=115200

13. LIMITES DA VERSÃO
---------------------

    - Sem envio de comandos ou cercas para coleiras
    - Sem autenticação
    - Sem mapa offline
    - Um gateway por instância
    - Sem expiração automática do estado da coleira
