VFENCE — EXPLICAÇÃO DO SERVIDOR LOCAL
======================================

1. O QUE É ESTE SERVIDOR
------------------------

Este servidor é a parte do projeto VFence que roda no Raspberry Pi (ou, para
testes, em um computador Windows). Ele não calcula a cerca virtual. Essa
responsabilidade continua sendo da coleira/ESP32.

O servidor recebe as mensagens que chegam do Gateway LoRa pela USB/Serial,
interpreta os dados, armazena um histórico local e mostra tudo em um dashboard
web acessível pela rede local.

O objetivo é permitir o fluxo abaixo:

    Coleira (GPS + geofencing)
               |
               | LoRa
               v
    Gateway LoRa (ESP32 Receiver)
               |
               | USB / Serial
               v
    Raspberry Pi (servidor VFence)
               |
               +--> SQLite: histórico local
               +--> API: dados para outras aplicações
               +--> Dashboard: visualização no navegador


2. O QUE O SERVIDOR FAZ
-----------------------

- Fica escutando uma porta Serial, como /dev/ttyUSB0 ou /dev/ttyACM0.
- Aceita o formato de teste LoRa já existente no projeto.
- Aceita o protocolo VFence V1 com posição, zona, satélites e HDOP.
- Salva telemetria no arquivo local vfence.db.
- Mantém o estado mais recente de cada coleira.
- Registra eventos quando a zona de uma coleira muda.
- Oferece endpoints HTTP/API.
- Atualiza o dashboard instantaneamente por WebSocket.
- Continua com o dashboard ativo quando o Gateway está desconectado.
- Tenta reconectar ao Gateway automaticamente.
- Possui modo mock para demonstrar tudo sem hardware.


3. GEOfencing: O QUE FICA NA COLEIRA
-------------------------------------

O servidor NÃO cria uma cerca virtual e NÃO decide se o animal está dentro ou
fora dela.

A coleira deve usar a solução de geofencing escolhida pelo grupo e enviar o
resultado da análise em uma zona, por exemplo:

    SEGURO
    ATENCAO
    CRITICO
    FORA
    GNSS_INVALIDO

Assim, se no futuro a lógica de geofencing ou a biblioteca usada mudar, o
Raspberry Pi e o dashboard não precisam ser reescritos. Eles apenas recebem e
exibem a zona enviada pela coleira.


4. FORMATOS DE MENSAGEM ACEITOS
--------------------------------

4.1. Formato de teste atual

O Sender/Receiver LoRa atual produz mensagens semelhantes a:

    Recebido: VFENCE_TESTE_630 | RSSI: -103 dBm | SNR: 6.50

O servidor entende esse formato e extrai:

    - sequência: 630
    - RSSI: -103 dBm
    - SNR: 6.50

Como esse formato não possui GPS ou zona, ele aparece como uma coleira de
teste chamada LEGACY no dashboard.

4.2. Protocolo VFence V1

O formato que a coleira deve enviar depois da integração é:

    V1|COL01|POS|-31.306119|-54.063935|SEGURO|12|0.90|630

Significado dos campos:

    V1          Versão do protocolo
    COL01       Identificador da coleira
    POS         Tipo de pacote: posição
    -31.306119  Latitude
    -54.063935  Longitude
    SEGURO      Zona calculada na coleira
    12          Número de satélites
    0.90        HDOP (qualidade do GPS)
    630         Número sequencial do pacote

O Receiver atual acrescenta RSSI e SNR ao imprimir a mensagem. O servidor
também aceita esta variação:

    Recebido: V1|COL01|POS|...|630 | RSSI: -103 dBm | SNR: 6.50


5. ARQUIVOS DO SERVIDOR
-----------------------

app/main.py
    É o ponto de entrada do FastAPI. Cria a API, serve o dashboard, inicia o
    leitor Serial e disponibiliza o WebSocket.

app/config.py
    Lê as configurações do ambiente, como porta Serial, baud rate, banco de
    dados e ativação do modo mock.

app/protocol.py
    Parser do protocolo. É responsável por validar mensagens recebidas. Ele
    verifica campos, zona, latitude, longitude, HDOP e sequência. Uma mensagem
    inválida é ignorada sem derrubar o servidor.

app/serial_reader.py
    Conecta ao Gateway pela Serial, lê linhas, chama o parser, salva pacotes
    válidos, registra logs e reconecta caso o Gateway seja desconectado.

app/database.py
    Cuida do SQLite. Cria tabelas, salva telemetria e consulta coleiras e
    eventos.

app/models.py
    Guarda a estrutura simples do estado do Gateway, por exemplo ONLINE,
    OFFLINE, porta usada e última mensagem.

app/realtime.py
    Gerencia os navegadores conectados por WebSocket e envia atualizações novas
    para todos eles.

app/templates/index.html
    Estrutura HTML da página principal do dashboard.

app/static/css/style.css
    Aparência visual do dashboard: cores, cartões, responsividade e estados de
    zona.

app/static/js/app.js
    JavaScript do navegador. Busca os dados iniciais pela API, abre o WebSocket
    e atualiza cartões, histórico e mapa sem recarregar a página.

scripts/mock_gateway.py
    Pequeno simulador que imprime pacotes V1. Útil para testes no terminal ou
    com portas seriais virtuais.

tests/test_protocol.py e tests/test_api.py
    Testes automatizados do parser e dos endpoints principais.

systemd/vfence.service
    Modelo de serviço para iniciar o servidor automaticamente quando o
    Raspberry Pi é ligado. Não é ativado automaticamente.

.env.example
    Modelo de configuração. Deve ser copiado para .env antes de executar.

requirements.txt
    Lista das bibliotecas Python necessárias: FastAPI, Uvicorn, pyserial,
    pytest e httpx.


6. BANCO DE DADOS SQLITE
------------------------

O arquivo vfence.db é criado localmente quando o servidor inicia. Ele contém:

collars
    Uma linha por coleira, com seu último estado conhecido: posição, zona,
    qualidade do GPS, sinal LoRa, sequência e última atualização.

telemetry
    Histórico completo dos pacotes válidos recebidos.

events
    Eventos relevantes. Atualmente registra a mudança de zona para evitar
    repetir eventos quando a coleira continua na mesma zona.

O banco é local. Não depende de internet ou nuvem.


7. API DISPONÍVEL
-----------------

GET /api/health
    Confirma que o servidor está ativo e informa o estado do Gateway.

GET /api/gateway
    Mostra porta Serial, última mensagem, status e eventual erro.

GET /api/collars
    Lista todas as coleiras conhecidas.

GET /api/collars/{collar_id}
    Mostra o estado atual de uma coleira específica.

GET /api/collars/{collar_id}/telemetry?limit=100
    Mostra o histórico de telemetria dessa coleira.

GET /api/events?limit=100
    Mostra as mudanças de zona mais recentes.

WS /ws
    WebSocket usado pelo dashboard para receber novos dados imediatamente.

GET /docs
    Página interativa com a documentação da API.


8. DASHBOARD
------------

O dashboard mostra:

- Gateway ONLINE ou OFFLINE.
- Porta Serial utilizada.
- Última mensagem recebida.
- Quantidade de coleiras detectadas.
- Para cada coleira: ID, zona, latitude, longitude, satélites, HDOP, RSSI,
  SNR, último horário e sequência.
- Mapa com as posições quando houver internet para carregar OpenStreetMap.
- Histórico de mudanças de zona.

As cores de zona são:

    SEGURO        Verde
    ATENCAO       Amarelo
    CRITICO       Laranja
    FORA          Vermelho
    GNSS_INVALIDO Cinza

Sem internet, o mapa pode não carregar, mas os cartões, banco, API e tempo
real continuam funcionando normalmente.


9. MODO MOCK
------------

O modo mock é uma demonstração sem Raspberry, GPS, LoRa ou Gateway físico.
Ele cria pacotes V1 com a coleira COL01 e alterna entre as zonas:

    SEGURO -> ATENCAO -> CRITICO -> FORA

Para ativar, coloque no arquivo .env:

    VFENCE_MOCK_SERIAL=true

O teste demonstrado no Windows usou esse modo. Ele comprovou que o parser,
SQLite, API, WebSocket, mapa, histórico e dashboard funcionam juntos.


10. COMO EXECUTAR NO WINDOWS
----------------------------

No PowerShell, dentro da pasta do projeto:

    & "C:\Users\leobo\AppData\Local\Programs\Python\Python312\python.exe" -m uvicorn app.main:app --env-file .env --host 127.0.0.1 --port 8000

Abra no navegador:

    http://127.0.0.1:8000

Para parar o servidor, pressione Ctrl+C no PowerShell que está executando o
Uvicorn.


11. COMO EXECUTAR NO RASPBERRY PI
---------------------------------

Instale os pré-requisitos:

    sudo apt update
    sudo apt install python3 python3-venv python3-pip

Na pasta do projeto:

    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    cp .env.example .env

Para modo mock:

    VFENCE_MOCK_SERIAL=true

Para Gateway real, configure por exemplo:

    VFENCE_MOCK_SERIAL=false
    SERIAL_PORT=/dev/ttyUSB0
    SERIAL_BAUD=115200

Inicie:

    uvicorn app.main:app --env-file .env --host 0.0.0.0 --port 8000

Descubra o IP do Raspberry:

    hostname -I

Abra de outro dispositivo da mesma rede:

    http://IP_DO_RASPBERRY:8000


12. INTEGRAÇÃO COM O GATEWAY REAL
---------------------------------

1. Conecte o ESP32 Receiver/Gateway ao Raspberry pela USB.
2. Identifique a porta com:

       ls /dev/ttyUSB*
       ls /dev/ttyACM*

3. Coloque a porta encontrada em SERIAL_PORT no .env.
4. Garanta acesso Serial ao usuário:

       sudo usermod -a -G dialout $USER

5. Saia e entre na sessão novamente, ou reinicie o Raspberry.
6. Desative VFENCE_MOCK_SERIAL.
7. Inicie o servidor.

Se o Gateway estiver desconectado, o dashboard mostrará OFFLINE e o servidor
tentará reconectar a cada poucos segundos.


13. PRÓXIMA ETAPA RECOMENDADA
-----------------------------

1. Estudar o código novo de geofencing em geofence/vfence.ino.
2. Confirmar qual solução/biblioteca de geofencing será usada na coleira.
3. Fazer a coleira montar o pacote V1 com GPS e zona calculada.
4. Transmitir esse pacote pela LoRa.
5. Usar o Receiver atual para repassá-lo ao Raspberry por USB.
6. Desativar o modo mock e demonstrar dados reais no dashboard.

O servidor já está pronto para as etapas 4, 5 e 6.
